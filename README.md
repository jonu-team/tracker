# Трекер задач

**Сайт: https://jonu-team.github.io/tracker/**

Статический сайт поверх GitHub Issues: доска, список очереди и страница задачи по образцу Яндекс Трекера. Задачи лежат в приватном репозитории `jonu-team/tasks`. Сайт собирается и публикуется на GitHub Pages через Actions, бэкенда нет.

## Вход

Каждый входит своим токеном GitHub. Токен хранится только в браузере (`localStorage`) и уходит только в `api.github.com`.

1. Откройте сайт и в блоке «Как выпустить токен» нажмите «форму токена в GitHub». Название и описание там уже заполнены.
2. **Resource owner** — `jonu-team` (по умолчанию стоит ваш аккаунт).
3. **Expiration** — например, **Custom** на год вперёд.
4. **Repository access** → **Only select repositories** → `tasks`. Не «Public repositories»: с ним токен не увидит приватный репозиторий.
5. **Permissions** → **Add permissions** → **Issues** и **Contents**, уровень **Read and write**.
6. **Generate token**, скопируйте токен (`github_pat_…`) и вставьте на сайте.

Для этого нужно быть участником организации `jonu-team`. Токен владельца организации одобряется сразу. Токен участника сначала одобряет владелец: Settings организации → Personal access tokens → Pending requests.

## Как хранятся задачи

- Задача — issue, ключ `DEV-N` — номер issue `#N`.
- Статус «Открыт», «Нужна информация», «В работе» — метки. «Закрыт» — закрытый issue.
- Тип «Веха» — метка.
- Чеклист, связи «связана с», вложения и сведения о переносе из Трекера — секции в конце описания со скрытыми маркерами `<!-- tt:… -->`. GitHub показывает их обычным markdown. Формат описан в [`src/domain/body.ts`](src/domain/body.ts).
- Картинки и файлы — в папке `attachments/` репозитория задач. Сайт загружает их через API с токеном.

Задачи можно править и в интерфейсе GitHub: отмечать пункты чеклиста, писать комментарии, менять описание. Строки, которые не подходят под формат секции, сайт переносит в описание, а не теряет.

## Разработка

```bash
npm ci
npm run dev        # http://127.0.0.1:5190
npm test
npm run build      # проверка типов и сборка в dist/
```

Демо-режим на локальной выгрузке Трекера (данные лежат в `.demo/` и в git не попадают):

```bash
npm run demo:fixture -- --viewer <логин GitHub>
npm run demo
```

## Перенос из Яндекс Трекера

```bash
cp migration.config.example.json migration.config.json   # пути к выгрузке, логины, репозиторий
node scripts/migrate.ts plan                             # сухой прогон: сводка и тела задач в migration-state/plan/
GITHUB_TOKEN=… node scripts/migrate.ts apply             # перенос; повторный запуск не создаёт дублей
GITHUB_TOKEN=… node scripts/migrate.ts verify            # сверка с выгрузкой по счётчикам и по каждой задаче
```

Номера сохраняются: в пустом репозитории задачи создаются по порядку, поэтому `DEV-N` становится `#N`. Если номер не совпадёт, скрипт остановится.

## Безопасность

- CSP мета-тегом: скрипты и стили только с самого сайта, запросы только к `api.github.com`, картинки только `blob:` и `data:`.
- Markdown проходит через DOMPurify. Внешние картинки показываются ссылками.
- Сторонних скриптов и CDN нет. Действия в workflow закреплены по SHA коммита.
- «Выйти» удаляет токен из браузера. Отозвать токен: GitHub → Settings → Developer settings → Fine-grained tokens.
